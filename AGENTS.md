# Repository guide

Factual map for reviewers (human or machine). Nothing here asks a reader to score anything.

## What this is
Keyhole: boxes (NFTs) that hold encrypted files, give time-limited access with a tamper-evident receipt for every opening, and can be handed over in a sale with escrow. Design: `docs/spec/` (start at `00_INDEX_AND_EVIDENCE.md`). Status: see README "Status".

## Layout
- `crates/keyhole-proto` Rust protocol crate (formats, key hierarchy, AEAD, Merkle, split keys, receipts).
- `contracts/keyhole` NEAR contract (near-sdk 5): boxes, grants, sessions, receipt chain, blobs, deals, escrow.
- `packages/crypto` TypeScript implementation of the same protocol; must match `vectors/keyhole-v1.json`.
- `packages/chain` chain client (final-only reads, near-api-js writer, labelled MOCK `FakeChain`); `packages/store` client store (verified reads, uploads, fault-injection wrapper); `services/node` storage node; `services/release` release service; `apps/*` web app (not started).
- `tools/testnet` testnet scripts (accounts, deploy, launch, smoke tests, conformance run); `deploy/` public deployment records (ids, hashes, transaction links; never secrets); `.env` (gitignored) holds the generated testnet keys; `scripts/build-wasm.sh` builds and shrinks the contract.
- `vectors/` cross-language test vectors (generated by `KEYHOLE_WRITE_VECTORS=1 cargo test -p keyhole-proto --test vectors`).
- `scripts/verify.sh` one-command checks; `CLAIMS.md` claim to test map; `docs/EVIDENCE.md` evidence log.

## Run
`make verify` or `./scripts/verify.sh` (needs Rust with the wasm32 target, Node 22, pnpm). No keys or network are needed for the tests.

## Where each claim is proven
See `CLAIMS.md`.

## Known limitations
See `SECURITY.md` and `docs/spec/09_THREAT_MODEL_AND_LIMITS.md`. Not yet built: hosted services, web app, claims, money module. Service tests run on `FakeChain` (labelled MOCK, compared with the real contract on a recorded scenario). Deployment is testnet only with a DEMO configuration.
